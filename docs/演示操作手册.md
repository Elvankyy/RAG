# 演示操作手册

> 适用版本：2026-10-24（前端 12 页 + 后端 M01–M06）
> 演示时长：约 15–20 分钟
> 推荐模式：**真实后端模式**（完整演示导入、权限、FAQ 挖掘与缓存闭环）；Mock 模式适合只看界面。

## 1. 演示目标

1. 登录后菜单按角色动态渲染。
2. 批量导入文档，拆分为知识单元并配置四维数据权限。
3. AI 问答只基于授权内容回答，未授权内容只提示数量。
4. 高频问题自动挖掘为 FAQ，审核发布后命中缓存加速。
5. 未命中问题进入知识缺口，可一键创建知识单元。
6. 看板展示访问量、Token、耗时与排行。
7. 组织、角色、菜单/操作权限可维护。

## 2. 启动准备

### 2.1 推荐：真实后端 + 真实前端

```bash
# 终端 1：重置演示数据并启动后端
cd backend
rm -f data/app.db data/app.db-wal data/app.db-shm
uv run uvicorn app.main:app --port 8010 --reload

# 终端 2：前端连接真实后端
cd frontend
VITE_USE_MOCK=false VITE_API_BASE_URL=http://127.0.0.1:8010 npm run dev -- --port 5175
```

访问：

- 前端：http://127.0.0.1:5175
- 后端 API 文档：http://127.0.0.1:8010/docs

后端首次启动会自动创建数据库并写入：7 个部门、6 个角色、7 个用户、5 个知识单元。

### 2.2 仅看界面：Mock 模式

```bash
cd frontend
npm run dev
```

默认 `VITE_USE_MOCK=true`，无需后端；页面数据来自 MSW，刷新页面会重置。

### 2.3 联调自检（可选）

```bash
cd frontend
npm run e2e:live
```

预期 8 项全部 PASS：登录、SSE 问答、知识单元、单元详情、看板、用户/角色/部门。

## 4. 演示文件

`demo-files/` 已准备 5 个文件，覆盖 4 种格式与不同权限场景：

| 文件 | 格式 | 建议权限 | 用途 |

## 5. 演示脚本

### 步骤 1：登录与角色菜单（2 分钟）

1. 打开 http://127.0.0.1:5175/login。
2. 使用 `km / Km@12345` 登录。
3. 观察左侧菜单：AI 对话、数据看板、知识导入、知识单元、知识沉淀；**没有组织架构**。
4. 退出后使用 `admin / Admin@123` 登录，观察新增「用户管理 / 角色管理 / 部门管理」。
5. 退出后使用 `alice / User@123` 登录，只保留「AI 对话」和个人中心。

**预期**：菜单由 `menu:*` 权限动态渲染；直接访问无权路由会跳转 403。

### 步骤 2：批量导入知识（3 分钟）

1. 用 `km` 登录，进入「知识导入」。
2. 点击「选择文件」，一次选中 `demo-files/` 下的 5 个演示文件（不要选 `README.md`），或直接拖入。
3. 分类填写 `演示知识`，标签填写 `演示,导入`。
4. 点击「开始导入」。
5. 观察任务表：每个文件显示解析/切片/向量化/索引阶段，最终状态为「已完成」。
6. 进入「知识单元」列表，搜索「食堂」或筛选分类「演示知识」，应看到新导入的单元。

**预期**：5 个文件全部成功；单元默认「未配置」数据权限，AI 暂时无法召回。

> Mock 模式差异：第 4 个文件会被模拟为失败，可点「重试」演示失败恢复。

### 步骤 3：配置四维数据权限（3 分钟）

1. 知识单元列表点击「食堂与班车服务指南」进入详情。
2. 切换到「数据权限」页签。
3. 勾选「全局公开」，点击「保存权限」；提示「数据权限已保存」。
4. 返回列表，进入「采购审批流程」，在「部门」中选择「财务部」，保存。
5. 进入「客户投诉处理规范」，在「个人」中选择「系统管理员」，保存。
6. 返回列表，确认「数据权限」列分别显示：全局公开 / 财务部 / 系统管理员。

**预期**：权限保存后立即生效；未配置权限的单元显示「未配置（无访问权限）」。

### 步骤 4：AI 授权问答与引用（3 分钟）

1. 退出，使用 `alice / User@123` 登录，进入「AI 对话」。
2. 输入：`食堂午餐几点开始？`，发送。
3. 观察流式回答、引用卡片（食堂与班车服务指南）、Token 用量。
4. 新建会话，输入：`年假有多少天？`，观察引用「员工手册（2026 版）」。

**预期**：回答只使用授权内容；引用卡片展示单元编号、分类与相关度。

### 步骤 5：未授权提示（2 分钟）

1. 退出，使用 `bob / User@123`（市场部）登录。
2. 输入：`采购审批需要哪些审批人？`。
3. 观察回答下方的权限提示：「另有 N 个相关知识单元因权限限制未展示」（N ≥ 1，取决于召回结果）。
4. 打开浏览器开发者工具 Network → `chat/stream`，确认 SSE 事件中只有 `unauthorized_count`，**没有未授权单元标题或正文**。

**预期**：不泄露标题、编号、正文；不把未授权内容拼入上下文。

### 步骤 6：FAQ 挖掘、审核与缓存（4 分钟）

1. 使用 `alice` 连续提问 3 次：`食堂午餐几点开始？`（每次可新建会话）。
2. 退出，使用 `km` 登录，进入「知识沉淀」。
3. 在「推荐审核」中找到该问题，显示推荐频次 ≥ 3。
4. 编辑标准答案，例如：`食堂午餐时间为 11:30–13:30，员工凭工牌就餐。`
5. 点击「通过并发布」。
6. 切到「已发布 FAQ」，确认缓存状态为「缓存生效」。
7. 使用 `alice` 再次提问同一问题。
8. 观察回答顶部徽标出现「FAQ 命中」，Token 显示 0，回答为编辑后的标准答案。

**预期**：挖掘阈值 3 次；审核发布后写入缓存；FAQ 命中时不调用检索与模型。

> Mock 模式不会根据提问动态挖掘，推荐列表为静态数据；完整闭环请使用真实后端模式。

### 步骤 7：FAQ 权限继承（可选，2 分钟）

1. 使用 `admin` 登录，进入「知识沉淀」→「手动新建 FAQ」。
2. 问题：`高管薪酬结构是什么？`；答案：`基本年薪、绩效年薪与长期激励。`
3. 关联知识单元选择「高管薪酬与股权激励方案（机密）」，创建并发布。
4. 使用 `bob` 提问同一问题。
5. 观察：**不命中 FAQ**，回答下方出现权限提示，正文不含「基本年薪」。

**预期**：FAQ 继承关联单元 ACL；无权用户不能命中缓存答案。

### 步骤 8：知识缺口与一键建档（3 分钟）

1. 使用 `alice` 提问：`火星出差补贴怎么申请？`（知识库无相关内容）。
2. 使用 `km` 登录，进入「知识沉淀」→「知识缺口」。
3. 找到该问题，查看提问频次与样例问题。
4. 点击「创建知识单元」，填写分类「行政管理」，提交。
5. 观察提示：已创建知识单元 `KU-...`，缺口状态变为「已解决」。
6. 可将另一条缺口点击「忽略」演示状态流转。

**预期**：低分/未命中自动进入缺口；权限不足（permission_miss）不会误记缺口。

### 步骤 9：数据看板（2 分钟）

1. 使用 `km` 登录，进入「数据看板」。
2. 查看指标卡：访问次数、独立用户、知识单元数、总 Token、平均响应。
3. 查看「按日访问趋势」「Token 消耗趋势」「响应时间分布」。
4. 查看「常见问题 TOP 5」「知识单元热度 TOP 5」。
5. 切换「近 7 天 / 近 14 天 / 近 30 天」并刷新。

**预期**：数据来自刚才的问答日志；FAQ 命中记录 Token 0，但仍计入访问次数。

### 步骤 10：组织与权限管理（2 分钟）

1. 使用 `admin` 登录，进入「用户管理」。
2. 新增用户：用户名 `demo`、密码 `Demo@123`、部门「技术部」、角色「普通用户」。
3. 重置密码、启停用、删除，观察状态与提示。
4. 进入「角色管理」，选择「知识管理员」，勾选/取消「审核 FAQ」，保存权限。
5. 进入「部门管理」，新增「演示部门」，再删除；尝试删除「技术部」（有成员），观察拒绝提示。
6. 使用 `km` 直接访问 `/org/users`，观察跳转 403。

**预期**：角色权限变更立即生效（重新登录或刷新权限缓存后）；删除有子部门/成员的部门被拒绝。

### 步骤 11：收尾

1. 退出登录。
2. 展示 `docs/验收报告.md` 的测试汇总与边界说明。

## 6. Mock 模式差异

| 项目 | 真实后端模式 | Mock 模式 |
|---|---|---|
| 数据持久化 | SQLite，刷新/重启保留 | 内存，刷新重置 |
| 知识单元 | 5 个种子 + 导入 | 12 个种子 |
| 会话 | 从空开始 | 4 个种子会话 |
| 导入 | 全部成功 | 第 4 个文件模拟失败，可重试 |
| FAQ 挖掘 | 提问 ≥ 3 次后动态生成 | 3 条静态推荐 |
| FAQ 命中 | 审核发布后命中 | 种子已发布 FAQ 可直接命中 |
| 看板 | 真实日志聚合 | 合成数据 |

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 后端端口被占用 | 改用 `--port 8011`，并同步修改 `VITE_API_BASE_URL` |
| 前端登录 401/网络错误 | 确认后端已启动、`VITE_API_BASE_URL` 正确、`CORS_ORIGINS` 包含前端地址 |
| 修改密码后立刻 401 | 改密会使旧 access/refresh 失效，需要重新登录 |
| 导入后搜索不到 | 确认任务状态「已完成」；Mock 模式可能失败，点重试 |
| FAQ 推荐列表为空 | 需 ≥ 3 次 answered 提问；进入页面会触发挖掘，可点「重新挖掘」 |
| FAQ 未命中 | 检查是否已发布、问题是否相似、关联单元权限是否允许当前用户 |
| 未授权提示数量为 0 | 只统计超过检索阈值的召回；确认提问确实命中受限单元 |
| 看板数据少 | 先进行几轮问答；切换时间范围后刷新 |
| 想清空演示数据 | 停止后端，删除 `backend/data/app.db*`，重新启动 |
